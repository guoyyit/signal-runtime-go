# signal-runtime-go

一个本地进程组内的信号运行时：多个受管进程共享同一 `Runtime`，外部调用方通过
统一入口（`Send` / `SendGroup`）向单个进程或整个进程组投递信号。运行时按
POSIX 风格完成待决排队、阻塞屏蔽、处置动作与交付，并支持崩溃后的状态恢复。

## 信号模型

- 标准信号：`1–31`（含 `SIGHUP`、`SIGINT`、`SIGKILL`、`SIGUSR1/2`、`SIGTERM`、
  `SIGCONT`、`SIGSTOP`、`SIGCHLD` 等命名常量）。同一进程对同一标准信号只保留
  **一个**待决实例（位图合并，重复投递不叠加）。
- 实时信号：`32–64`（`MinRT`–`MaxRT`）。每次投递都排队，按到达顺序交付，
  同一信号可有多条待决记录。
- `SIGKILL` 与 `SIGSTOP` 不可捕获、不可阻塞、不可忽略：为其配置非默认处置
  返回 `ErrInvalidSignal`；`SetMask` 会把它们从屏蔽字中静默剔除；即使“配置了
  处理器”也永远执行默认动作。

## 队列上限策略（实时信号）

每个进程的实时待决队列容量为 **32**（`rtQueueCap`）。队列满时采用
**丢弃最新（drop-newest）**策略：

- 新到达的实时信号被丢弃，**不**入队；
- 本次 `Send` / `SendGroup` 返回 `ErrQueueOverflow`（组投递会继续投递其余成员，
  并返回首个错误）；
- 进程的丢弃计数器加一，可通过 `Overflow(pid)` 读取。

丢弃是显式的（错误 + 计数器），运行时绝不静默丢失信号：调用方总能区分
“已交付 / 已排队 / 因溢出被丢弃”。

## 屏蔽与处置

- `SetMask` 替换进程屏蔽字；被阻塞的信号保持待决，解除阻塞后立即按顺序规则交付。
- `SetAction` 配置处置：`ActionDefault`（默认动作）、`ActionIgnore`（丢弃）、
  `ActionHandler`（自定义处理器，按名字注册于 `HandlerRegistry`）。
- 处理器执行期间，有效屏蔽字 = 当前屏蔽字 ∪ `HandlerMask` ∪ {该信号}
  （`NoDefer: true` 时不加入该信号本身）；处理器返回后恢复原屏蔽字。
  可用 `Mask(pid)` 在处理器内观察到该叠加效果。
- 交付按进程串行化：同一进程的处理器不会被重入打断，同信号处理器绝不会
  打断正在执行的同信号处理器；处理器内再次 `Send` 的信号在外层处理器
  返回后按序交付。

## 交付顺序规则

每次交付循环按以下规则选取下一个信号，直到没有可交付信号为止：

1. 进程处于停止态时，只考虑 `SIGKILL` 与 `SIGCONT`，其余信号保持待决。
2. 否则取**未被阻塞的、编号最小**的待决信号——标准信号（1–31）因此总是
   先于实时信号（32–64）交付。
3. 同一实时信号的多个实例按到达先后（FIFO）交付。

交付循环会一次性排空所有可交付信号，新到达的信号在下一轮循环交付，因此
低编号信号不会饿死高编号信号：任何已解除阻塞的信号都会在当前循环内被交付。

## 默认动作

| 信号 | 默认动作 |
| --- | --- |
| `SIGCHLD` | 忽略 |
| `SIGSTOP` | 停止进程（并丢弃待决的 `SIGCONT`） |
| `SIGCONT` | 继续进程（并丢弃待决的 `SIGSTOP`）；即使被捕获也照样恢复运行 |
| 其余全部（含实时信号） | 终止进程，记录致死信号（`Exited` 可查） |

## 停止与继续

- 停止期间到达的信号（除 `SIGKILL`/`SIGCONT`）全部保持待决，实时队列不丢失。
- `SIGCONT` 恢复运行后，积压信号按上述顺序规则交付；对停止的进程组做
  `SendGroup(SIGSTOP/SIGCONT)` 不会丢失任何成员的任何信号。
- `SIGKILL` 可终止停止态进程。

## 可中断等待

- `Wait(pid, timeout)` 阻塞至被 `Wake` 唤醒或超时（返回 `nil`）。
- 等待期间交付**被捕获**的信号：先执行处理器，然后——
  - 处置含 `Restart: true`：以剩余时间继续等待；
  - 否则：`Wait` 返回 `ErrInterrupted`。
- 被阻塞（未交付）的信号不打断等待；进程终止使 `Wait` 返回 `ErrProcessExited`。
- 竞争确定性规则：信号到达与等待超时的竞争，以**先在进程锁上提交的一方**
  为准——中断先提交则返回 `ErrInterrupted`，超时先提交则返回 `nil`，
  结果确定，不会出现第三种状态。

## 并发与确定性

- 所有运行时方法可并发调用；每个进程的状态由互斥锁保护，交付循环按进程
  串行化（`delivering` 标志保证同一进程同一时刻只有一个交付循环）。
- 并发投递不会丢失或重复交付：实时信号的入队顺序即获取进程锁的顺序，
  溢出时按 drop-newest 显式失败。
- 组投递按 pid 升序逐一投递，成员在投递期间的退出不影响其余成员。

## 崩溃恢复

- `Snapshot()` 序列化全部可恢复状态：每个进程的处置配置（处理器按注册名
  保存）、屏蔽字、标准待决位图、实时待决队列、溢出计数、停止与退出状态。
- `Restore(data, registry)` 重建运行时：待决信号**恰好恢复一次**——恢复本身
  不交付，随后按 pid 升序做一次交付扫描，使未阻塞且未停止的待决信号被交付，
  既不重复也不丢失；停止态进程保持停止，待 `SIGCONT` 后再交付。
- 恢复时注册表缺少某个处理器名字：处置配置保留，交付时回退为该信号的
  默认动作。
- 非法快照数据返回错误；队列中的非法信号条目在恢复时被丢弃。

## API 概览

| 方法 | 说明 |
| --- | --- |
| `New(reg)` / `Spawn(pgid)` | 创建运行时 / 在进程组中创建进程 |
| `Send(pid, sig)` / `SendGroup(pgid, sig)` | 向进程 / 进程组投递信号 |
| `SetMask(pid, set)` / `Mask(pid)` | 替换 / 读取屏蔽字 |
| `SetAction(pid, sig, action)` / `ActionOf(pid, sig)` | 配置 / 读取处置 |
| `Pending(pid)` / `Overflow(pid)` | 查询待决队列 / 丢弃计数 |
| `Stopped(pid)` / `Exited(pid)` | 查询停止 / 退出状态 |
| `Wait(pid, timeout)` / `Wake(pid)` | 可中断等待 / 唤醒 |
| `Snapshot()` / `Restore(data, reg)` | 状态快照 / 崩溃恢复 |

## 测试

```sh
go test -race ./...
```

测试覆盖：标准信号合并、实时信号 FIFO 与溢出策略、屏蔽字叠加与 NoDefer、
同信号处理器不可重入、不可捕获信号、停止/继续（含进程组）、组投递、
并发投递不丢不重与无饿死、可中断等待与 Restart、快照恢复不丢不重。
